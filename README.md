# نماز قضا و روزه قضا | محاسبه

اپلیکیشن اندرویدی فارسی و راست‌به‌چپ برای برآورد شخصی، ثبت و پیگیری نماز و روزه قضا. طراحی با پالت زمردی، طلایی و کرم و پشتیبانی از حالت روشن/تیره انجام شده است.

## وضعیت فاز اول

### پیاده‌سازی‌شده

- پروفایل اختیاری با جنسیت، بازه شروع/پایان برآورد، تقویم پیش‌فرض و منطقه زمانی IANA
- برآورد خام قابل بازبینی از روی بازه تاریخ؛ تغییر برآورد بدون حذف تاریخچه و با حفظ تعدادهای انجام‌شده
- ذخیره هم‌زمان پروفایل و اعمال برآورد در یک تراکنش Room؛ اگر هر بخش شکست بخورد، پروفایل و بدهی‌های قبلی با هم حفظ می‌شوند
- ثبت جداگانه پنج نماز و روزه، شمارنده‌های پایدار، ثبت گروهی از طریق مقدار اولیه و تاریخچه رویدادها؛ محافظ ثبت در برابر درخواست هم‌زمان و دوبارکلیک سریع
- اصلاح مقدار انجام‌شده به‌صورت رویداد قابل بازگردانی؛ بازگردانی ثبت قدیمی در صورت وجود تغییرات بعدی به‌صورت ایمن رد می‌شود
- ثبت اختیاری بازه‌های عادت ماهانه، نفاس، بیماری و سایر عذرها؛ هیچ‌کدام بدون قاعده فقهی منبع‌دار به‌طور خودکار از بدهی کم نمی‌شوند
- موتور دامنه مستقل از UI با `ObligationRuleSet` برای قواعد تفکیک‌شده نماز و روزه، نسخه قاعده و منبع؛ تا زمان انتخاب مرجع و اتصال قواعد بازبینی‌شده، خروجی صریحاً نیازمند بررسی است
- تبدیل تاریخ میلادی، شمسی و قمری محاسباتی مدنی با Android ICU؛ تبدیل روزمحور بر مبنای UTC برای جلوگیری از جابه‌جایی روز در DST و استفاده از منطقه زمانی ذخیره‌شده کاربر
- تقویم ماهانه با تقویم پیش‌فرض انتخابی کاربر (شمسی/میلادی/قمری مدنی) و نمایش هم‌زمان سه تاریخ؛ قالب ورود تاریخ پروفایل نیز از همان ترجیح پیروی می‌کند. تاریخ قمری مدنی ممکن است با رؤیت هلال/تقویم رسمی محل تفاوت داشته باشد
- برنامه‌ریز روزانه/هفتگی، هدف مستقل نماز و روزه، محاسبه زمان تقریبی پایان، یادآور WorkManager و نمایش وضعیت واقعی مجوز/اعلان برنامه؛ محاسبه تأخیر یادآور با Instant و ZoneId برای عبور درست از تغییر ساعت تابستانی
- گزارش پیشرفت مجزای نماز و روزه، نمودار میله‌ای هفت‌روزه نماز/روزه، نوار پیشرفت، جست‌وجو و فیلتر دسته‌ای در تمام تاریخچه (نه فقط ۲۰ رکورد آخر) و وضعیت‌های خالی/خطا
- پشتیبان‌گیری و بازیابی فایل با PBKDF2-HMAC-SHA256 و AES-256-GCM؛ اعتبارسنجی نوع/ساختار داده قبل از جایگزینی و restore اتمیک داخل تراکنش Room
- بازیابی اضطراری از صفحه خطای دیتابیس به یک فایل دیتابیس رمزگذاری‌شده تازه؛ فعال‌سازی با pointer اتمیک پس از restore موفق، بدون حذف/بازنویسی فایل قبلی و با پاک‌سازی فایل موقت در شکست
- حذف کامل داده‌های محلی با تأیید صریح کاربر
- راهنمای آفلاین برای ثبت بدهی، برنامه‌ریزی، تقویم، پشتیبان‌گیری و محدودیت‌های فقهی برنامه
- فونت فارسی Vazirmatn v33.003 با وزن‌های Regular/Medium/SemiBold/Bold تحت SIL Open Font License؛ منبع رسمی https://github.com/rastikerdar/vazirmatn و فایل مجوز در `app/src/main/assets/fonts/OFL.txt` نگهداری می‌شود. متن عربی قرآن برای حفظ نشانه‌گذاری Uthmani از فونت Serif سیستم استفاده می‌کند.
- جهت چیدمان RTL در theme به‌صورت سراسری اعمال و با تست instrumentation مستقل بررسی می‌شود.
- ناوبری در عرض‌های بزرگ به Navigation Rail تبدیل می‌شود و محتوای صفحات در نمایشگرهای عریض حداکثر عرض خوانا دارد؛ در عرض‌های باریک Navigation Bar پایین صفحه حفظ می‌شود.
- Room schema version 6 با migrationهای افزایشی 1→2→3→4→5→6؛ migration ششم پانوشت‌های اصلی ترجمه QuranEnc را بدون حذف cache قبلی اضافه می‌کند
- SQLCipher Android 4.20.0 با کلید تصادفی دیتابیس محافظت‌شده توسط Android Keystore و AES-GCM؛ Android Auto Backup و Device Transfer غیرفعال‌اند
- آیه روز واقعی: متن عربی بدون تغییر از Tanzil Uthmani v1.1 و ترجمه فارسی Rowwad از QuranEnc با پانوشت‌های اصلی مترجم به‌صورت عیناً حفظ‌شده. تفسیر فارسی As-Saadi فقط در build توسعه (debug) قابل مشاهده است؛ در build انتشار دریافت، نمایش، ورود از backup و خروج به backup آن غیرفعال است تا شرایط اختصاصی بازنشر از ناشر تأیید شود.
- cache محلی آیه روز برای استفاده آفلاین؛ هنگام بازشدن برنامه ابتدا نسخه محلی نمایش داده می‌شود و سپس در پس‌زمینه به‌روزرسانی می‌شود؛ اگر فقط آیه روزهای قبل cache شده باشد، تاریخ آن صریحاً نمایش داده می‌شود و به‌عنوان آیه امروز جا زده نمی‌شود
- GitHub Actions workflow برای تست واحد، ساخت APK و اجرای instrumentation؛ در صورت دسترسی runner به KVM از Android 16 استفاده می‌شود و در نبود KVM به Android 15 + TCG برمی‌گردد، چون Android 16 + TCG در runner فعلی پس از boot نیز ADB property fetch را پاسخ نمی‌دهد. targetSdk/compileSdk همچنان 36 است.

### مواردی که عمداً فعال نشده‌اند

- **قواعد فقهی نهایی:** کاربر هنوز مرجع تقلید را مشخص نکرده است و قواعد بازبینی‌شده/منبع‌دار برای مراجع مختلف به پروژه متصل نشده‌اند. انتخاب شناسه مرجع صرفاً ترجیح ذخیره‌شده است و هیچ حکم یا کاهشی اعمال نمی‌کند. فدیه و کفاره نیز هنوز محاسبه نمی‌شوند.
- **محاسبه خودکار عادت ماهانه/نفاس:** بازه‌ها به‌صورت خصوصی ذخیره می‌شوند؛ تا زمان تأیید قاعده مستند مرجع انتخابی، از محاسبه خودکار کنار گذاشته نمی‌شوند. برآورد خام روزه حکم شرعی نیست.
- **صوت تلاوت عربی:** Quran Foundation API برای endpointهای تلاوت به `x-auth-token` و `x-client-id` نیاز دارد. این اطلاعات نباید داخل APK قرار گیرند؛ اتصال backend امن و مجاز هنوز ارائه نشده است. در build انتشار پخش و ورود/خروج URL صوتی از backup غیرفعال است.
- **حدیث روز فارسی:** interface مستقل `HadithContentProvider` و نتیجه `Unavailable` آماده است؛ provider عمداً هیچ متنی تولید نمی‌کند. API رسمی Sunnah.com به API key نیاز دارد و پیاده‌سازی فعلی آن فقط عربی/انگلیسی را ارائه می‌کند. برای فعال‌سازی، کلید دسترسی و یک منبع ترجمه فارسی دارای مجوز لازم است. تا آن زمان حدیث یا درجه اعتبار ساختگی نمایش داده نمی‌شود.
- **چرخش کلید دیتابیس:** کلید فعلی در Android Keystore محافظت و در خطاها fail-closed است، اما API چرخش/تعویض کلید SQLCipher درون‌برنامه‌ای هنوز پیاده‌سازی نشده است. برای استفاده از گذرواژه جدید پشتیبان، فایل تازه بسازید؛ فایل‌های قبلی همچنان گذرواژه قبلی را می‌خواهند.
- **مجوز تفسیر فارسی:** شرایط عمومی بازنشر QuranEnc صریحاً ترجمه‌ها را پوشش می‌دهد، اما شرایط مستقل بازنشر تفسیر فارسی As-Saadi هنوز تأیید نشده است؛ این موضوع پیش‌نیاز انتشار عمومی است.
- همگام‌سازی ابری، حساب کاربری، ویجت، ثبت صوتی، دستیار هوشمند و آرشیو کامل قرآن/حدیث در فازهای بعدی قرار دارند.

## منابع محتوایی و مجوز

- متن عربی: Tanzil Quran Text Uthmani v1.1، فایل اصلی در `app/src/main/assets/quran/tanzil_uthmani_v1.1.txt` بدون تغییر نگهداری شده است. مجوز CC BY 3.0 و شروط کپی verbatim/no modification در `TANZIL_NOTICE.txt` کنار فایل درج شده است. منبع و به‌روزرسانی: https://tanzil.net/download/ و https://tanzil.net/updates/.
- ترجمه فارسی: Rowwad Translation Center از QuranEnc؛ متن ترجمه بدون بازنویسی نمایش داده می‌شود و عنوان/نسخه/منبع در UI ذکر می‌شود. API: https://quranenc.com/fa/home/api .
- تفسیر فارسی: Tafsir As-Saadi، کلید `persian_saadi`، نسخه رسمی API برابر 1.0.0 در زمان اتصال؛ مسیر debug-only است. صفحه رسمی اثر را ترجمه فارسی تفسیر معرفی می‌کند، اما بندهای بازنشر صفحه فقط «ترجمه‌ها» را نام می‌برند و حق بازنشر این نسخه تفسیری را جداگانه روشن نمی‌کنند؛ تا تأیید صریح ناشر و شناسایی مترجم فارسی، release build آن را غیرفعال نگه می‌دارد.
- تلاوت: اتصال امن Quran Foundation هنوز نیازمند backend و credentials است؛ مستندات: https://api-docs.quran.com/docs/content_apis_versioned/4.0.0/chapter-reciter-audio-file/ و شرایط: https://api-docs.quran.com/legal/developer-terms/ .
- حدیث: مستندات API رسمی و نیاز به کلید: https://sunnah.com/developers .

## فناوری و معماری

- Kotlin 2.2.10، Android Gradle Plugin 9.5.0، Gradle 9.6، KSP
- Jetpack Compose، Material 3، MVVM، Coroutines/Flow
- Room 2.8.5، SQLCipher Android 4.20.0، Android Keystore، AES-GCM
- اگر فایل دیتابیس یا WAL/SHM آن موجود باشد ولی envelope یا کلید Keystore مفقود شده باشد، کلید جایگزین ساخته نمی‌شود تا دیتابیس رمزگذاری‌شده با کلید اشتباه باز نشود.
- بازشدن واقعی دیتابیس رمزگذاری‌شده در پس‌زمینه هنگام راه‌اندازی بررسی می‌شود؛ تا پایان بررسی صفحه بارگذاری نمایش داده می‌شود و خطای کلید، فایل یا migration پیش از ورود به جریان اصلی به صفحه بازیابی هدایت می‌شود. SQLCipher پیش از هر ورودی از جمله WorkManager بارگذاری می‌شود.
- بازیابی خودکار فایل پشتیبان به دیتابیس تازه در حالت خرابی خود دیتابیس یا کلید هنوز پیاده‌سازی نشده و به بررسی فنی نیاز دارد؛ صفحه فعلی در این وضعیت راهنمای محافظت از داده است.
- Android ICU برای تبدیل تقویم‌ها بدون بسته‌بندی دیتای حجیم ICU4J؛ WorkManager برای یادآورهای زمان‌بندی‌شده
- مرزبندی `domain` / `data` / `ui` / `notifications` در ماژول app؛ ساختار فعلی تک‌ماژولی است اما مرزهای قابل استخراج به Gradle modules حفظ شده‌اند

## ساخت و آزمون

JDK 17 لازم است. Android SDK Platform 36 باید نصب باشد. مسیر SDK محلی در `local.properties` تنظیم می‌شود و این فایل نباید commit شود.

```powershell
./gradlew.bat testDebugUnitTest
./gradlew.bat compileDebugAndroidTestKotlin
./gradlew.bat assembleDebug
./gradlew.bat lintDebug
```

APK دیباگ: `app/build/outputs/apk/debug/app-debug.apk`.

تست‌های واحد شامل محاسبات بدهی، جلوگیری از overflow، تبدیل تقویم، رفتار موتور قواعد فقهی نامشخص، برنامه‌ریز و رمزنگاری فایل پشتیبان است. تست‌های instrumentation برای migration Room، بازگردانی backup، رد فیلدهای JSON با نوع نامعتبر پیش از تغییر داده، حفظ تاریخچه، جلوگیری از undo ناسازگار، بازشدن SQLCipher با کلید نادرست، cache آیه قدیمی و متن Tanzil اضافه شده‌اند. Workflow مخزن اجرای آن‌ها را روی Android 16 emulator انجام می‌دهد.

## محدودیت‌های اعتبارسنجی فعلی

- آخرین `clean testDebugUnitTest compileDebugAndroidTestKotlin assembleDebug lintDebug` روی JDK 17 در محیط محلی موفق بوده است: ۲۷ تست واحد موفق، صفر شکست/skip، compile موفق instrumentation، صفر خطای Lint و ۷ هشدار نسخه‌ای.
- تست‌های instrumentation در محیط محلی فقط کامپایل شده‌اند؛ دستگاه و AVD در محیط توسعه موجود نیستند. اجرای runtime در CI برای آخرین SHA پس از push باید جداگانه تأیید شود.
- targetSdk فعلی 36 است؛ آزمون سازگاری روی دستگاه‌های Android 16 و نسخه‌های بالاتر هنوز انجام نشده است.
- زمان‌بندی WorkManager دقیق/AlarmClock نیست و سیستم‌عامل ممکن است اعلان را در حالت Doze یا Battery Saver به تأخیر بیندازد.
- این پروژه هنوز برای انتشار عمومی/فروشگاهی تأیید یا منتشر نشده است.
